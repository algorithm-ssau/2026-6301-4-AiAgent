# Alcohol Censor

Курсовой проект по теме «ИИ-агент для цензуры», обучающиеся группы 6301-020302D.

## О проекте

Рост российского рынка онлайн-видео требует автоматизированной модерации контента: аудитория VK Видео в декабре 2025 года составила 81,5 млн пользователей, Rutube в первом квартале 2026 года — 83,7 млн человек. Ручная модерация трансляций не масштабируется, а законодательство обязывает скрывать рекламу алкоголя. Проект решает эту задачу автоматически.

Программа захватывает видеопоток с экрана, обнаруживает алкоголь нейросетью в реальном времени и закрывает его чёрными прямоугольниками через прозрачный оверлей поверх любого контента. Работает на Windows и Linux.

## Запуск

### Готовый EXE

Скачайте установщик из раздела [Releases](../../releases) и запустите его. После установки откройте `AlcoholCensor.exe`. Обученная модель автоматически размещается в `C:\Users\<username>\AppData`.

### Из исходников

```bash
pip install -r requirements.txt
python main.py
```

Откроется окно управления — выберите модель, выставьте порог уверенности и нажмите «Включить цензуру».

Файл модели `Models/best.onnx` должен быть в папке проекта. Если его нет — запустите обучение (см. ниже).

### Linux

```bash
sudo pacman -S xdg-desktop-portal pipewire gstreamer gst-plugin-pipewire \
               gst-plugins-base python-dbus python-gobject gtk-layer-shell
python main.py
```

### AMD GPU

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/rocm7.1
```

Видеокарта определится автоматически.

```bash

```

Скачивает датасет с Roboflow (7332 изображений, 5 классов алкоголя), обучает модель и предлагает сохранить результат в `Models/best.onnx`.

## Архитектура

Общая схема работы:

```
Захват экрана → YOLO → Сглаживание треков → Оверлей
```

Система состоит из трёх независимых модулей: `Core` (логика захвата, детекции и трекинга), `Overlay` (отрисовка прямоугольников на экране) и `Models` (файлы обученных моделей). Такая структура обеспечивает кроссплатформенность и позволяет заменять отдельные компоненты без переписывания остального кода.

Программа работает в четырёх потоках: захват кадров, детекция и трекинг, статистика FPS, отрисовка оверлея. Скорость — около 20 FPS на CPU с ONNX-моделью.

### Модель

Для детекции используется YOLO26n в формате ONNX. По сравнению с RT-DETR-R18 она менее точна, но значительно быстрее — что критично для работы в реальном времени.

Модель обучена на датасете AlcoholDetection (7332 изображений, 5 классов: `alcohol-bottle`, `beer-bottle`, `beer-glass`, `shot`, `wine-glass`). Разбивка: 81% обучение, 10% валидация, 9% тест. Разрешение входа — 640×640. Применялась аугментация: случайное кадрирование, поворот, изменение яркости, оттенка, экспозиции, размытие и зашумление.

| Модель | mAP@50 | Precision | Recall |
|--------|--------|-----------|--------|
| Наша (YOLO26n) | 74,9% | 88,1% | 80,4% |
| Roboflow 3.0 Fast | 86,1% | 90,7% | 78,1% |

### Ограничения

- Ложные срабатывания возможны на объектах, визуально схожих с целевыми классами, и при плохом освещении.
- Пропуски детекции возможны при быстром движении объектов.
- Алкоголь в мультипликациях не детектируется.

### Модули

**`Core/capture.py`** — захват экрана. Абстрактный интерфейс с двумя реализациями: `mss` для Windows и X11, PipeWire через xdg-desktop-portal для Linux. Поддерживает несколько мониторов и ограничение частоты захвата.

**`Core/detector.py`** — детекция через YOLO. Поддерживает `.pt` и `.onnx` модели. При загрузке ONNX автоматически выбирает лучший доступный провайдер ускорения (NVIDIA, AMD, Intel или CPU). Для `.pt` определяет устройство через PyTorch.

**`Core/tracker.py`** — сглаживание координат детекций между кадрами. Сопоставляет новые детекции с существующими треками по пересечению рамок и расстоянию между центрами. Применяет EMA-фильтр для плавного движения прямоугольников и удерживает рамку ещё несколько кадров после потери объекта.

**`Core/utils.py`** — потокобезопасный счётчик FPS на скользящем окне.

**`Overlay/windows/overlay_win.py`** — прозрачное окно поверх рабочего стола на Windows. Пропускает клики мыши, всегда поверх других окон, не захватывается скриншотером.

**`Overlay/linux/overlay_lin.py`** — аналог для Linux на GTK3.

**`gui.py`** — интерфейс управления на tkinter: выбор модели, порог уверенности, выбор монитора и целевого FPS.

**`main.py`** — точка входа, защита от двойного запуска через системный мьютекс.

**`train.py`** — скрипт загрузки датасета, обучения и экспорта модели в ONNX.

### Михаил — сглаживание треков
`Core/tracker.py`, `Tests/test_tracker.py`

Написал модуль `TrackSmoother`, который превращает «дёрганые» выходные координаты нейросети в плавные стабильные прямоугольники на экране. Основная задача — координаты от YOLO приходят в пространстве 640×640, а нужно рисовать на реальном разрешении монитора, поэтому первым делом делается пересчёт с учётом отступа монитора. Затем каждый новый прямоугольник сопоставляется с уже известными треками по степени перекрытия и расстоянию — это нужно, потому что YOLO не отслеживает объекты между кадрами. После сопоставления применяется EMA-фильтр: новая позиция берётся как взвешенное среднее между прошлой и текущей, что даёт плавное движение. Если объект временно пропал из детекции, рамка не исчезает сразу, а удерживается ещё несколько кадров — это убирает мигание при кратковременных пропусках. Написал тесты для всех этих случаев. Дополнительно дорабатывал интерфейс и исправлял баги по ходу интеграции.

### Артём Сурков — оверлей Windows
`Overlay/windows/overlay_win.py`, `Core/utils.py`

Написал два компонента. Первый — `FpsCounter`, потокобезопасный счётчик на скользящем временном окне: каждый обработанный кадр отмечается вызовом `tick()`, а `get()` возвращает среднюю частоту за последние пару секунд. Второй и основной — `WindowsOverlay`, прозрачное окно поверх всего экрана на Windows. Окно создаётся через Win32 API с флагами прозрачности и click-through — мышь и клавиатура работают в обычных приложениях под ним, как будто окна нет. Рисование прямоугольников реализовано через GDI с двойной буферизацией, чтобы не было мерцания при обновлении. Обновление списка прямоугольников из потока детекции сделано через очередь сообщений Win32 — это единственный корректный способ взаимодействия с окном из другого потока.
